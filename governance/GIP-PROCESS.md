# GAUNTLET Improvement Proposal process — proposed

**Status: proposed, not yet ratified.** Use `governance/gips/GIP-0000-template.md` for submissions. GIP states: DRAFT → DISCUSSION → SECURITY_REVIEW (when relevant) → TSC_DECISION → ACCEPTED/REJECTED/DEFERRED → IMPLEMENTED → RELEASED. An accepted GIP is not proof of tested code, independent evidence or a released protocol.

A GIP records author, stakeholders, affected contract versions, threat model, compatibility, test vectors, local verification evidence, conflict disclosures, recorded decision and appeals. Trust-role changes require separate Trust Council procedure. Breaking security guarantees require an explicit major protocol version and cannot be waived through routine release approvals. Security-sensitive information uses responsible disclosure rather than public exploit payloads.
